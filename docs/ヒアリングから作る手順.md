# ヒアリング回答から、お店の口コミアプリを作る手順（Claude 向け）

スタッフが Notion の「口コミアプリ ヒアリング台帳」から「Claudeへの指示」をコピーして Claude に貼ると、この手順で作業する。
貼られた文章の【 】の項目が、お客様のフォーム回答。

前提: Claude Code（デスクトップアプリの Code タブ）で、作業フォルダを `CODE/moveact-kuchikomi` にして使う。
ファイルを触れない Claude（claude.ai のチャットなど）に貼られた場合は、手順 2 の JSON と手順 5 の確認表を出すだけにして、「Claude Code で続きを行ってください」と伝える。

## 守ること（ここは崩さない）

- **ステマ規制への対応はどのお店も同じ。** 確認チェック3つ（実体験・店舗関係者でない・規約同意）はアプリ側で必ず出る。外す・弱める設定は作らない。
- **【口コミの特典・指示をしないことへの同意】が「同意あり」でなければ作らない。** スタッフに「同意が取れていないので作れません。お客様に確認してください」と返して止める。
- **回答に無いメニュー名・選択肢を足さない。** 足りないときは空けずに、スタッフに確認を頼む。
- 選択肢・メニュー名・説明に、断定や誇張の言葉（必ず／絶対／確実に／100%／完全に／治る／No.1／ナンバーワン／最高／最強／最安／日本一／世界一／他店より／奇跡／魔法／劇的／痩せる）を入れない。お客様の回答に入っていたら言い換え、言い換えたことを確認表に書く。
- **本番の DB 登録・Coolify の設定は、三上様の承諾を得てから。** この手順の中で勝手に行わない。
- 既存のお店（`tenants/*.json`、本番の tenants）は書き換えない。

## 手順

### 1. 読む
- `docs/店舗の追加手順.md`（全体の流れ）
- `tenants/example.json`（JSON の形）
- `shared/tenantConfig.ts`（設定項目の意味）

### 2. `tenants/<slug>.json` を作る

| JSON | どこから | 決め方 |
|---|---|---|
| `slug` | 【希望のアドレス名】 | 英小文字・数字・ハイフンだけ。空なら店名をローマ字にして短く（例：sakura-seikotsu）。`tenants/` に同じ名前があれば別の名前にする |
| `hosts` | slug | `["<slug>.kuchikomi.s-toru.com"]`。【独自ドメイン】があればそれも足す |
| `notifyCode` | 【月次レポートの送り先コード】 | 空なら `null` |
| `config.brandName` | 【店舗名】 | そのまま |
| `config.logoLetter` | 【店舗名】 | 先頭の1文字（英字なら大文字） |
| `config.footer` | 【店舗名】【店舗一覧】 | `店舗名 — 所在地（都道府県＋市区町村まで）`。店舗が複数なら所在地を「・」でつなぐ |
| `config.industry` | 【業種】 | 「その他」なら【業種（その他の内容）】を使う |
| `config.words.service` | 【受けるものの呼び方】 | 例：施術／レッスン |
| `config.words.place` | 【店内の呼び方】 | 例：店内／院内／スタジオ／サロン |
| `config.words.staff` | 【担当者の呼び方】 | 例：施術者／スタッフ／インストラクター |
| `config.words.frequency` | 【来店頻度の呼び方】 | 例：通院頻度／来店頻度 |
| `config.options.purpose` | 【来店目的・お悩み】 | 1行1つ。12文字くらいまでに短く。最大10個。最後に「その他」を必ず入れる |
| `config.options.staff` | 【スタッフの強み】 | 1行1つ。最大6個。「丁寧な説明」「話しやすい」のような、お客様が選べる形にする |
| `config.options.atmosphere` | 【お店の良いところ】 | 1行1つ。最大6個 |
| `config.options.frequency` | 決まり | `["初めて", "数回目", "定期的に通っている", "久しぶり"]`（通う形でないお店は「定期的に利用している」に） |
| `config.colors` | 【ブランドカラー】 | 下の「色の決め方」 |
| `config.ogImage` | 書かない | 共有画像は別途用意したときだけ |
| `config.monthlyLimit` | 決まり | `100`（月額に含むAI作成の上限。運用手順書の「月100件まで」）。三上様から別の数を指示されたときだけ変える |
| `stores` | 【店舗一覧】【GoogleマップのクチコミURL】 | 1行1店舗。`name`・`address`・`area`（市区町村＋町名くらい。AIが本文に一度入れる地域名）・`googleMapsUrl`・`slug`（英字。main／店舗の地名のローマ字） |
| `menus` | 【メニュー】 | 1行1つ「名前／説明」。説明が無ければ空文字。`slug` は英字 |

色の決め方:
- 指定が無ければ `colors` を書かない（Moveact と同じ落ち着いた色になる）
- 指定があれば `brand` にその色。`brandSoft` はその色をとても薄くした色（白に近い）。`primary` はボタンの色で、白い文字が読める濃さにする（明るすぎる色なら少し暗くする）。`primaryLight` は primary を少し明るくした色

GoogleマップのクチコミURL:
- `https://g.page/r/.../review` か、Googleマップの「クチコミを書く」が開くURLであること
- お店のホームページやGoogle検索のURLだったら、作るのを止めずに確認表に「要確認」と書く

### 3. 形を確かめる（書き込まない）

```bash
npm run add-tenant -- tenants/<slug>.json
```

エラーが出たら JSON を直して、通るまで繰り返す。

### 4. 手元で画面を見る

手元のDB（`.env` の `kuchikomi_dev`）にだけ入れる。本番には入れない。

1. `tenants/<slug>.json` を元に、`hosts` を `["<slug>.localhost"]` に変えた写しをスクラッチパッドに作る
2. `npm run add-tenant -- <写し> --apply`（手元のDBにもう同じ slug があれば、この手順は飛ばす）
3. `.claude/launch.json` の server と vite を起動し、`http://<slug>.localhost:5174` を開く
4. スマホ幅（375px）で、店名・色・質問・メニューが回答どおりか、はみ出しが無いかを見て、スクリーンショットを撮る

### 5. スタッフに見せる

次の確認表を出す。

| 項目 | 内容 |
|---|---|
| お店のアドレス（予定） | `https://<slug>.kuchikomi.s-toru.com` |
| 画面に出る名前 | |
| 店舗（Googleの口コミURL） | |
| メニュー | |
| 質問の選択肢（目的／強み／良いところ） | |
| 言い換えた言葉 | （あれば） |
| 要確認 | （あれば） |

スクリーンショットも添える。

### 6. コミットする

`tenants/<slug>.json` を、ブランチ `tenant/<slug>` にコミットする。main には入れない。

### 7. 本番に出すのは三上様の承諾のあと

確認表を三上様に見ていただき、承諾を得てから次を行う。

1. 本番DBに登録する（足すだけ。ほかのお店に影響しないので、日中でもよい）:
   `cat tenants/<slug>.json | ssh root@163.44.103.9 'docker exec -i -w /app $(docker ps --format "{{.Names}}" | grep ^op7cede4d1v24i72qn39txs7 | head -1) npx tsx server/db/addTenant.ts - --apply'`
2. Coolify にドメインを足して再デプロイする作業は**夜間**に行う。夜間キュー `~/.claude/scheduled-tasks/shittoru-advisory-board/night-queue/` に .md を置く（書き方は同じフォルダの README.md）。承諾の欄に、三上様の言葉と日付を書く
3. 反映後、`https://<slug>.kuchikomi.s-toru.com` を開いて確認する
4. Notion の台帳の「ステータス」を「公開」にし、「アプリのURL」を入れるよう、スタッフに伝える
