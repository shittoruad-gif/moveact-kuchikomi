# 口コミ作成アプリ お店の追加手順

1つのアプリ（Coolify の `moveact-kuchikomi`）で、複数のお店を動かします。
どのお店の画面を出すかは、**開かれたドメイン**で決まります。
お店を足すときに、新しいアプリ・新しいデータベース・新しいサーバーは要りません。

## 全体の形

```
kuchikomi.moveact.net          ─┐
sample.kuchikomi.s-toru.com    ─┼─ 同じアプリ（Coolify: moveact-kuchikomi）─ 同じDB（moveact_kuchikomi）
（お店の独自ドメインも可）      ─┘        ドメインを見て tenants からお店を決める
```

- お店ごとの設定（店名・色・質問の選択肢・言葉づかい・月次レポートの送り先）は `tenants` テーブルにあります
- 店舗・メニュー・下書きの記録は `tenant_id` でお店ごとに分かれています。ほかのお店のデータは見えません
- ステマ規制への対応（実体験の確認・店舗関係者でないことの確認・規約への同意）は、どのお店でも同じものが出ます。お店ごとに外すことはできません

## 最初に1回だけ（済んでいれば飛ばす）

### 1. DNS：`*.kuchikomi.s-toru.com` をサーバーに向ける

s-toru.com のDNSを管理している画面（ネームサーバーは `ns-cloud-e1〜e4.googledomains.com`）で、レコードを1つ足します。

| 種類 | ホスト名 | 値 |
|---|---|---|
| A | `*.kuchikomi` | `163.44.103.9` |

これで `どんな名前.kuchikomi.s-toru.com` でもサーバーに届くようになります。お店ごとにDNSを触る必要はありません。
（`kuchikomi.s-toru.com` そのものは、紹介LPで使っています。上のレコードはその下の名前だけが対象なので、LPには影響しません）

### 2. 本番DBの移行

アプリの起動時に自動で行います（`server/db/migrate.ts`）。足すだけで、既存の行は変えません。
済んでいれば何もしません。初めて反映した夜は、ログに `[migrate] ... を足しました` が出ていることを確認します。
念のため、初回の反映の前に本番DBのバックアップを取っておきます。

## お店を1つ足す（毎回）

### 1. ヒアリング内容を JSON に書く

`tenants/example.json` をコピーして `tenants/<slug>.json` を作ります。

| 項目 | 書くこと |
|---|---|
| `slug` | お店の英字の名前（英小文字・数字・ハイフン）。ドメインにも使う |
| `hosts` | このお店のドメイン。例：`["<slug>.kuchikomi.s-toru.com"]` |
| `notifyCode` | しっとる通知ハブのご契約コード。月次レポートを送らないなら `null` |
| `config.brandName` | 画面の一番上に出す名前（必須） |
| `config.logoLetter` | ロゴの代わりに出す1文字（必須） |
| `config.footer` | 画面の一番下の1行（必須） |
| `config.industry` | 業種。AIへの説明に使う（必須）。例：整骨院 |
| `config.colors` | 色。省略すると Moveact の色 |
| `config.words` | 言葉づかい。`service`（施術／レッスン など）、`place`（院内／店内／スタジオ）、`staff`（施術者／スタイリスト）、`frequency`（通院頻度／来店頻度） |
| `config.options` | 質問の選択肢（来店目的・担当者の印象・雰囲気・頻度） |
| `config.ogImage` | LINEで共有したときの画像。用意しなければ書かない（出さない） |
| `config.monthlyLimit` | 1か月にAIで下書きを作れる回数（1店舗あたり。アプリが店舗数を掛ける）。契約書どおり 100。書かなければ上限なし |
| `stores` | 店舗（店名・所在地・地域名・Googleの口コミ投稿URL）。1つだけなら画面で選ばせずに決まる |
| `menus` | メニュー（名前・説明） |

満足度の選択肢は、AIの書き方の切り替えに使っているので変えられません。
**提供していないメニュー名を書かないこと。**

### 2. 中身を確かめてから入れる

```bash
cat tenants/<slug>.json | ssh root@163.44.103.9 'docker exec -i -w /app $(docker ps --format "{{.Names}}" | grep ^op7cede4d1v24i72qn39txs7 | head -1) npx tsx server/db/addTenant.ts -'
```

表示された店名・ドメイン・店舗・メニューが正しければ、最後に ` --apply` を付けてもう一度流します（`... addTenant.ts - --apply`）。
同じ slug・同じドメインのお店がもうあれば、何も書き込まずに止まります。

### 3. Coolify にドメインを足す（夜間）

Coolify の `moveact-kuchikomi` → Domains に、カンマ区切りで `https://<slug>.kuchikomi.s-toru.com` を足して保存し、**再デプロイ**します。
HTTPS の証明書は Coolify が自動で取ります。再デプロイは日中にしない（ご利用中のお客様がエラーに当たる）。

### 4. 確認

- `https://<slug>.kuchikomi.s-toru.com` を開き、店名・色・質問・メニューがそのお店のものになっていること
- `https://kuchikomi.moveact.net` が今までどおり Moveact のままであること
- スマホ幅（375px）ではみ出しがないこと

## 店頭QRコードと、お礼メッセージの文面

- 店頭のQRコードは `npm run qr -- tenants/<slug>.json` で作る（中身は `https://<slug>.kuchikomi.s-toru.com/?via=qr`。`qr/<slug>/` に PNG と SVG ができる）
- 来店後のお礼メッセージ（LINE・予約システム・メール）に入れる文面は `npm run thanks-message -- tenants/<slug>.json` で出す。リンクには `?via=thanks` が付く
- 月次レポートに「どこから開かれたか（店頭のQRコード／お礼メッセージ／その他）」が出る
- お店に渡すときは「全員に同じ文面で送る・特典を付けない・文面を変えない」のお願いを必ず添える（Googleの口コミのルールとステマ規制のため）

## 解約したとき（契約書第10条・第11条）

1. 解約のお申し出の日を含む課金期間が終わったら、提供を終える（データは消さない）
   ```bash
   ssh root@163.44.103.9 'docker exec -w /app $(docker ps --format "{{.Names}}" | grep ^op7cede4d1v24i72qn39txs7 | head -1) npx tsx server/db/endTenant.ts <slug> --apply'
   ```
   そのお店のアドレスを開くと「ご利用を終了しました」と出て、作成も記録もできなくなる。月次レポートも止まる
2. UnivaPay の継続課金を止める（`shittoru-automation/apps/contract-onboarding/docs/スタッフ手順書_解約と定期課金の停止`）
3. **三上様の承諾を得てから**、来店客のデータを消す（取り消せない）
   ```bash
   ... npx tsx server/db/endTenant.ts <slug> --delete-data --apply
   ```
   消えるのは来店客のデータと作成回数だけ。お店の設定と月次レポートの送信記録は残る
4. 夜間の反映のときに、Coolify の Domains からそのお店のドメインを外す

## お店の独自ドメインを使いたいとき

お店の側のDNSで `kuchikomi.お店のドメイン` を A `163.44.103.9` に向けてもらい、
`hosts` と Coolify の Domains にそのドメインを足します。

## 月次レポート

毎月1日 9時以降に、`notifyCode` のあるお店だけへ、しっとる通知ハブ経由で送ります（同じお店の同じ月は二度送りません）。
Moveact は 2026-10-01 の指示で止めています（`notifyCode` なし）。

手で数字を出すとき：

```bash
node scripts/monthly-report.mjs 2026-10 --tenant=<slug>
```

## 手元での確認

```bash
npm run seed          # 手元のDBを移行し、Moveact の店舗・メニューを入れる
npm run add-tenant -- tenants/example.json --apply   # hosts を ["example.localhost"] にして入れる
npm run server        # 別のターミナルで npm run dev
```

`http://moveact.localhost:5174` と `http://example.localhost:5174` で、それぞれのお店の画面が開きます。
